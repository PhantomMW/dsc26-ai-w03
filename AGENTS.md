# Tawseel COD failure-risk model — AI & Deep Tech pod

## Environment and checks
- Use Python 3.12; install the locked environment with `uv sync`.
- Run the full test suite with `uv run pytest`; do not use a system Python or unpinned dependencies.
- Run a baseline evaluation with `uv run python -c "from tawseel.data import make_parcels; from tawseel.model import add_history_features, time_split, compare_to_baseline; d=add_history_features(make_parcels(4000, seed=42)); train,test=time_split(d); print(compare_to_baseline(train,test,seed=42))"`.
- Repeat the evaluation for seeds 21, 42, and 73; record model PR-AUC, dummy PR-AUC, lift, and Brier scores in `RESULTS.md`.

## Data, models, and artefacts
- Synthetic data is generated by `tawseel.data.make_parcels`; read `tawseel/data.py` for its schema and generation logic.
- Treat `tawseel/data.py` as DSC-owned: do not edit it; the grader replaces it with its own copy.
- The implementation belongs in `tawseel/model.py`; public tests are in `tests/test_public.py`.
- This task persists no trained model artefacts; build an unfitted pipeline with `build_pipeline(seed)` and fit it only on training data.
- Approved estimator stack is the pinned scikit-learn 1.9.1 in `pyproject.toml`: `LogisticRegression` for the model and `DummyClassifier(strategy="prior")` for the baseline.
- Keep dependencies exactly as pinned in `pyproject.toml` and `uv.lock`; do not add packages without a task requirement.

## Modelling rules
- Use only `FEATURE_COLUMNS` plus `customer_prior_parcels` and `customer_prior_fail_rate`; never use `parcel_id`, `courier_notes`, `delivered_at`, or `failed` as model inputs.
- History is point-in-time: only strictly earlier `created_at` rows for the same customer count; equal timestamps must not see one another.
- Build history features before the chronological split; preserve input index and row order, and never mutate the input DataFrame.
- Split chronologically using the README's ceil rule; every row tied at the boundary timestamp belongs in test.
- Keep imputers, encoders, scaling, and text vectorization inside the sklearn Pipeline to prevent preprocessing leakage.
- Handle unseen categories, missing numeric/category values, and empty `address_text`; ignore extra DataFrame columns.
- A ROC-AUC near 0.99 is a leakage warning; the README flags ROC-AUC above 0.9 as leakage on this synthetic task.

## Evaluation and delivery
- Fit every estimator on the training partition only; evaluate probabilities on the held-out test partition.
- Compare against the prior-only dummy; report PR-AUC lift and Brier score, not accuracy alone.
- Do not claim real-world delivery performance from synthetic data; state this limitation in `RESULTS.md`.
- Update `AI_USAGE.md` when AI assistance materially contributes, including a rejected/fixed suggestion and how it was tested.
